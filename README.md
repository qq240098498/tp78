# tp78 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。

除了模块，还可以用全局的两级**分组**与模块内的**标签**把文案再组织一层：分组能改名、上下移动、换父分组，标签能改名与删除；筛选区可以按分组、标签与某种语言是否已填译文叠加筛选，条件之间取交集。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5078>

端口固定为 `5078`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存文案时会记下是谁改的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 分组区列出全局的两级分组树，可以新增一级分组、给一级分组加子分组、改名、上移/下移、移动到别的分组下面或顶层、删除
5. 文案区可以展开“标签管理”：先选模块，再给这个模块新增、改名或删除标签；编辑文案时也能临时给当前模块新建标签并立即勾选
6. 文案区顶部可以按模块、分组、标签、某几种语言是否已填译文叠加筛选，也可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
7. 点新建文案，填上模块、文案键、所属分组、标签与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
8. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言、分组、标签与文案都会先确认

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

## 分组与标签的约定

- 分组在模块之外全局通用，一条文案最多属于一个分组；分组最多两级，子分组不能再挂子分组
- 分组名在同一层（同一个父分组下，或都是一级分组）不能重复，忽略大小写；不同层允许重名
- 把分组挪到它自己下面、或挪到它自己的子分组下面，会在保存时当场拒绝；一个还挂着子分组的一级分组不能整体降成子分组
- 分组的父子关系与同层先后顺序每次移动、排序后立即落盘，重启服务或重新打开页面后保持不变
- 删除分组不会删除文案：挂在它上面的文案变为“未分组”，它的子分组自动提升为一级分组
- 标签按模块维护，一条文案可以打多个标签，但只能打自己模块的标签；标签名在同一个模块内不能重复（忽略大小写），跨模块允许重名
- 标签可以改名与删除；删除标签只会把这个标签从相关文案上摘掉，不会删除任何文案

## 筛选与分页的约定

- 模块、分组、标签、译文填写情况与关键词之间全部取交集
- 分组选中一个一级分组时自动带上它下面所有子分组；另有“只看未分组”
- 标签可多选，选中多个时命中任意一个即可；每种语言可以各自要求“已填译文”或“未填译文”，列出的语言条件逐条都要满足
- 同一份数据，无论筛选条件传进来的先后如何，结果集合与条目顺序都完全一致
- 列表按模块、文案键、id 排序后再按条数上限分页，翻页拼接不会出现重复条目，也不会漏掉条目

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "groups": [...], "tags": [...], "entries": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

每次读写都会顺手把数据整理成一致的结构：分组只保留两级、悬空父引用提到第一层、同层重名补序号；标签同模块重名补序号；文案身上挂着的已删除分组或跨模块标签会被自动摘掉。

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/groups            | 分组清单（扁平有序，按 parentId 拼两级树），附带各组文案数 |
| POST   | /api/groups            | 新增分组（name、parentId）                   |
| PATCH  | /api/groups/:id        | 改名、移动（parentId）与排序（afterId）      |
| DELETE | /api/groups/:id        | 删除分组，文案改挂“未分组”，子分组提升       |
| GET    | /api/tags              | 标签清单，可按 `?module=` 过滤，附带引用条数 |
| POST   | /api/tags              | 新增标签（module、name）                     |
| PATCH  | /api/tags/:id          | 标签改名                                     |
| DELETE | /api/tags/:id          | 删除标签，只摘掉文案上的引用，不删文案       |
| GET    | /api/entries           | 文案列表，支持模块、分组、标签、译文与关键词叠加筛选及分页 |
| POST   | /api/entries           | 新增文案（可带 groupId 与 tags）             |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案（可改分组与标签）                   |
| DELETE | /api/entries/:id       | 删除文案                                     |

`GET /api/entries` 的查询参数：

- `module`：模块名，精确匹配
- `groupId`：分组 id，自动包含其全部子分组；传 `__none__` 只看未分组
- `tag`：标签 id，可重复出现表示多个标签取并集
- `trans`：形如 `zh-CN:filled`（已填译文）或 `zh-CN:missing`（未填译文），可重复出现，之间取交集
- `keyword`：同时匹配文案键与任意一种语言的译文
- `limit`、`offset`：分页，默认每页 200 条、最多 1000 条；返回体带 `total`、`hasMore`

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
